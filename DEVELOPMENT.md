## Principles

These principles apply uniformly to both repositories (AstroUI and
[AstroStack](https://github.com/x42en/astro-stack)). Examples below are
TypeScript-flavoured.

1. **English only.** Code, comments, commit messages, pull requests,
   documentation and any user-visible string are written in English. No mixed
   languages.

2. **Documentation comments.** Every exported function, class, hook, store,
   and component carries a JSDoc/TSDoc comment suitable for autogenerated
   documentation.

   ```ts
   /**
    * Stack the supplied light frames using the configured rejection algorithm.
    *
    * @param frames - Calibrated light frames.
    * @param rejection - One of `winsorized` | `sigma` | `percentile`.
    * @returns The persisted master-light path.
    */
   export async function stackLights(frames: Path[], rejection: Rejection): Promise<Path> { … }
   ```

3. **Strict typing.** TypeScript runs in `strict` mode. **`any` is
   forbidden** — reach for `unknown`, generics, `Record<…>` or a discriminated
   union first. If `any` is genuinely required, leave a comment explaining why
   and call it out in code review.

4. **Variable typing.** Annotate variables when the inferred type is not
   obvious or when the value crosses an API boundary.

5. **Single responsibility.** Each module does one thing. Each component
   renders one concept. Split before you cross the readability threshold.

6. **Reuse before duplication.** Shared types live in `src/types/`, constants
   in `src/lib/`, presentational primitives in `src/components/ui/`. Extract
   on the second occurrence, never wait for the third.

7. **File size.** Target **under 500 lines** per file; **hard ceiling at
   1 000**. Split a file before it grows past the target.

8. **Fail fast and loud.** Validate inputs at boundaries (store actions,
   service functions, form submitters) and throw with a clear message. Inside
   the perimeter, **do not** add defensive null checks for states that cannot
   occur — let the error surface.

9. **No backward compatibility during migrations.** A breaking change ships
   with the migration that performs it; the old code path is removed in the
   same commit, not deprecated for an unbounded period.

10. **No dead code.** Remove unused imports, exports, functions, props and
    branches in the same PR that orphans them. ESLint flags them — fix the
    warning, do not disable the rule.

11. **No duplication.** If you copy logic, extract it.

12. **Tests for every public surface.** New hooks and stores ship with unit
    tests; new pages ship with at least one rendering test; bug fixes ship
    with the test that would have caught the bug.

13. **Clean commits.** One logical change per commit. Tests pass on every
    commit.

14. **Quality gates green before pushing.** `npm run typecheck` and
    `npm run lint` must pass locally before you push.

## Project layout

```
src/
  types/             Shared interfaces & aliases. No imports from other layers.
  services/          REST calls (Axios). Returns typed data or throws.
  store/             Zustand stores (settingsStore, uiStore, authStore).
  hooks/             Reusable React side-effect hooks (useUploadQueue, useWebSocket).
  lib/               Pure utilities (axios client, presets, query client).
  components/
    auth/              Route guards (RequireAuth, RequireAdmin).
    branding/          Logo (mark / wordmark / glyph variants).
    gallery/           Gallery cards, lightbox, email-download modal.
    landing/           Landing-page sections + carousel.
    layout/            AppShell, Header, PublicHeader, UserMenu, Sidebar.
    processing/        ProcessingPanel, ProgressPanel, MetadataCartouche, OutputActions.
    profiles/          ProfileForm, ProfileList, StepSection.
    sessions/          SessionCard, SessionFilters, CreateSessionModal.
    ui/                Reusable primitives (Modal, Skeleton, Toast, …).
  pages/             Route-level views.
public/              Static assets shipped as-is (logo.svg, background.jpg).
```

Boundary rules:

- `services/` only know about HTTP. They do not import React or stores.
- `store/` only own client state; server state belongs to TanStack Query.
- `components/` never import from `services/` directly — they call hooks or
  receive props.
- `pages/` compose components, wire queries/mutations, and handle navigation.

## Local setup

### Prerequisites

- Node.js ≥ 20
- A running [AstroStack](https://github.com/x42en/astro-stack) backend
  (locally or via Docker).

### Bootstrap

```bash
git clone https://github.com/x42en/astro-ui.git
cd astro-ui
cp .env.example .env       # set VITE_API_BASE_URL, VITE_WS_BASE_URL
npm install
npm run dev                # http://localhost:5173 with HMR
```

The preview build ships a **mock authentication store**: any non-empty
credentials succeed; the username `admin` unlocks the Settings area. Real
authentication is on the roadmap.

## Coding standards

### Components

- One component per file. Co-located private sub-components are fine while the
  file stays under the 500-line target.
- **Named exports only** — no `export default` for components.
- Props typed via an `interface` declared above the component.
- Avoid inline object/array literals in JSX props that defeat memoisation —
  extract them with `useMemo` / `useCallback` when needed.
- Do not use `useEffect` for data fetching. Use TanStack Query.

### State management

- Cross-component client state → Zustand store in `src/store/`.
- Server state → TanStack Query. Do not duplicate it in Zustand.
- Local UI state (modal open, form draft) → `useState`.
- Persisted stores must `partialize` to avoid storing ephemeral data.

### Styling

- Tailwind utility classes only. No standalone `.css` files outside
  `src/index.css` and no `style` props for anything Tailwind can express.
- Use the design-system tokens from `tailwind.config.js`
  (`primary`, `accent`, `space-bg`, `space-elevated`, `text-primary`,
  `text-secondary`, `text-muted`, `success`, `warning`, `error`).
- Stick to the 8-point spacing scale. Avoid arbitrary values
  (`p-[13px]`) unless documented inline.

### Errors

Throw `Error` (or a subclass) from store actions and services. Components
catch and surface user-visible errors via the `Toast` system; never swallow
errors silently.

## Testing

The current preview build has limited automated coverage. New code is expected
to ship with at least one of:

- **Unit tests** for hooks and stores (jest-style assertions on pure logic).
- **Integration tests** for pages (React Testing Library, mocked services).
- **Type tests** — TypeScript itself is a test; do not weaken types to make
  the compiler happy.

Continuous quality gates in CI:

```bash
npm run typecheck     # tsc --noEmit
npm run lint          # ESLint
```

## Adding a feature

Typical recipe for a new page that consumes a new backend capability:

1. Add or extend the type in `src/types/`.
2. Add the call in `src/services/<area>.ts`.
3. Wrap it with `useQuery` / `useMutation` in the page or a small hook.
4. Build the UI under `src/components/<area>/` using the existing primitives.
5. Add the route in `src/App.tsx` with the appropriate guard
   (`RequireAuth`, `RequireAdmin`, or none for public).
6. If the route should appear in the navigation, add it to `Header.tsx`
   (or `PublicHeader.tsx`).
7. Update [README.md](./README.md) features table if user-visible.

Adding a reusable component:

1. Drop it under `src/components/ui/` (or the closest domain folder).
2. Export it as a named export.
3. Add JSDoc + a `Props` interface.
4. Use it in at least two places before keeping it as "shared".

## Common pitfalls

- **Importing across layers** — components calling `axios` directly,
  services importing from `store/`, etc. Re-read the boundary rules above.
- **Stale TanStack Query cache** — when a mutation invalidates server state,
  call `queryClient.invalidateQueries` with the right key (or use the
  `onSuccess` hook of the mutation). Do not refresh the page in code.
- **WebSocket reconnects** — the AppShell owns one WebSocket. Do not open
  another from a page; subscribe via the existing event hooks.
- **localStorage drift** — bumping the shape of a persisted store without
  bumping its `name` will deserialise stale data. Either migrate explicitly
  or rename the key.
- **Tailwind purge** — class names assembled at runtime via string
  concatenation are invisible to Tailwind's purge. Always write full class
  names in source, or list them in `safelist`.
